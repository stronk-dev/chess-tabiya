## Summary

Compute the three existing choice-card operands from original complete legal populations in the
existing worker. Persist them in a separate complete-cut family and adopt it through every
current consumer, preserving metrics, cohorts, zero observations, floors and source absence.

## Problem and measured result

The three existing Profile residuals still call decisionTraitPopulation in HTTP-side deriveRunFact.
The original legal/candidate/centre sources now exist, but the claimed worker prefix deliberately
cannot issue a live decision. Moving computation to opportunity rows changes the metric: they
omit forced/unanimous decisions and store alternative-only shares.

The disposable experiment compares43position/chosen sample calls and284candidate-member visits
through original source factories against the existing helper. For both colors, legal sets of4and6
with one chosen pawn move have residuals3/4and5/6 but the same calculated opportunity-algebra tuple.
There are no persisted trait opportunity rows in that experiment. Zero residuals remain in the
average. Its23.76ms finite run is not worker/Profile delivery cost. Existing200-game worker/Profile
measurements are baselines for the previous implementation, not proof of this one.

## Scope

Replace the three current helper-derived choice operands with original source facts computed in
the existing worker and read from its completed cut. Preserve metric definitions,100/200/100game
floors, existing standard-start/primary/played cohort, per-decision weighting, by-game bootstrap,
contributors, consent and account lifecycle. Delete these helper reads from learner delivery after
adoption; no legacy parallel implementation is required. The old helper may remain test/research
code. GAME facts, opportunity rows, clocks, engine grades, habits-as-skills and bot policy remain
separate. No new learner setting, LLM authority, feature metric or generic reducer framework.

## 1. Original claimed decision

Reuse the exact original store-opened ProfileGameSource and its validated replay/entire graph,
image, owner, source digest, revision and claim/rebuild checks. Do not replay again per decision.
Add a private finite choice-decision handle selected from that scope by an original decision ref.
The issuer, not its caller, resolves the actual normativeDecisions entry, primary branch member,
outgoing move.committed event, original BEFORE node and AFTER child. Only decisionClass=played
with original owner authorship is eligible. Imported source-game moves and predictions cannot
become played decisions. Preserve the existing imported-continuation cases where the actual
current normative algebra proves an owner's played continuation.

Retain run/owner/cut/revision, branchId, before/after node IDs, original eventSeq, canonical
beforeFen/moveUci/afterFen, rooted BEFORE sourcePly and actual mover color. The selected chosen
identity must be the outgoing event's exact canonical legal member. Repeated FENs do not identify
a decision; FEN fullmove count, creation timestamps and classifyPhase do not supply rooted index.
Owner authorship comes from the existing normative source/journal, never configured learnerSide
alone. An actual owner move with a different board color is not relabelled as an opponent by color.

The supported learner-role domain is the actual store-issued image's single_player disposition
AND an original proved owner MOVE for this decision (the D4144 standing boundary). Normative
owner authorship alone can be an academy teacher action. Shared/legacy/coach/native-match roles
without this proof remain selected cohort decisions with role_unavailable, never silently dropped,
marked cohort-ineligible or encoded false. Their historical learner-role sources remain owed by
D4140; this companion neither invents nor permanently descopes them. Do not import GAME's separate
all-own-side path test: decision-level owner proof may cover either actual board color.

The handle is privately issued and checked through the existing scope's lifetime; copies, foreign
images, old claims, crossed refs, source changes and retired scopes refuse. Renewal of the same
genuine current claim works. Terminal success/failure/drain/conflict and rebuild replacement retire
work; a new claim cannot resurrect an old handle. Use existing checkpoint/renewal callbacks, not
another scheduler, grant, hash store, lease or background process.

**Finite actor-decision exception to foundation-source-identity §3.8:** only for
profile.choice_facts@1, this original claimed owner-played decision plus the complete original
source/member joins below supplies the actor_decision authority instead of a live
ContextualFoundationOccurrence. As with the parent's separate GAME exception, no live occurrence
envelope is manufactured. This does not admit any other source consumer, actor, recorded event,

The choice row cannot be passed back as a contextual occurrence or factory source authority.

This handle is NOT a FoundationRecordedDecision live grant. Keep live decision/occurrence/clock
issuers' refusals intact. Only the early-queen candidate factory gains a finite typed input union
over genuine live decisions and this original claimed choice-decision. Its private context reader
does exact owner lookup in those two stores, never a caller-written authority object, ply, boolean
or callback. Other live readers must continue refusing the worker handle. The @1 early-queen
source's allowed context wording explicitly becomes live-or-original-claimed-choice; its payload,
rooted<16 convention, candidate meaning and exactness are unchanged. This amendment is authorized
only after this RFC's acceptance; it is not permission to broaden generic recorded contexts.

The source change includes its complete existing factory boundary: closed input descriptor,
source-operand normalization/digest, original invocation recording/reread and constructor/value
authority fixtures. A worker handle must not hash as an empty opaque object or be accepted only
at the outer guard and then refused by the invocation rereader. Normalize its actual private
authority after the early-queen route's typed check; keep live occurrence adapters' original
live-only readers and negative controls. Refresh the real source ABI/coupled declarations through
their normal generators; do not hand-stamp an authority receipt or weaken original-input checks.

## 2. One finite source consumer

Register profile.choice_facts@1 / consumeProfileChoiceFacts in the real manifest, runtime/server
operation census and actual worker/rebuild path. Its exact accepts are legal_moves@1,
candidate_role@1, pawn_extended_center_destination@1 and early_queen_move@1 under their existing
rules.mobility.reading IDs. Operator-only, analysis/background, machine_condition/fact, existing
pack/position/imported session vocabulary, provider-off available, maxFacts=null/maxForms=1,
latency120000ms. Exact declared adapters and source-absence rules must match before any factory.
This is a complete variable-size legal population, not a four-item UI budget.

For each eligible original decision, obtain one original legal-map value at its BEFORE, retain
every unique canonical member and exactly one chosen identity. For each member invoke candidate
role from that identical legal-map instance, centre from that identical role, and early queen
from that identical role and original decision handle. Check original invocation inputs/source
membership, not merely equal payloads. Nonmatches are available empty. Throws, invalid authority,
crossed roots or duplicate/missing members cannot become false flags or a smaller population.
No engine, Maia, full tactical candidate packet or semantic event census is required for these
literal source traits; existing worker families continue their own normal processing unchanged.
Only the three adopted candidate/centre/early-queen source dispositions cease advertising no
consumer; leave unrelated experimental sources and actor/semantic qualification holds intact.

For N legal identities retain integer counts P,C,Q and chosen booleans p,c,q. Source role is the
BEFORE piece, so all four promotions remain pawn choices. Centre uses the eight declared squares.
Canonical castling identities remain unique king-to-rook members; physical destinations are not
additional choices. Queen counts use source role for all decisions; early-queen matches must equal
those queen members precisely when original BEFORE sourcePly<16 and be empty otherwise. Never
substitute generic opening phase. The actual existing source predicate stays the authority.

## 3. Separate closed choice family

Add a separate derived family/table, not fields in GAME facts or opportunity observations. Bump
the existing derivation revision at implementation and use the claimed next migration against
the actual head; no hard-coded future number in the draft. No run/pack/event rewrite. Publish,
delete and rebuild all families under the same original completed-cut transaction.

One family document per run/cut carries exactly:

```
learnerId, runId, completedSeq, derivedRev, observedAt, primaryBranchId,
cohort: ineligible(reason: not_standard_start | no_primary_played_decision)
     | eligible(decisions: nonempty ordered ChoiceDecision[])

ChoiceDecision:
  ref: { nodeId: AFTER, eventSeq, beforeNodeId, sourcePly: BEFORE }
  beforeFen, moveUci, afterFen, moverColor, phase
  result: available {
    legalUcis: unique nonempty canonical string[],
    counts: { pawn, centerPawn, queen },
    chosen: { pawn, centerPawn, queen }
  } | unavailable(reason: source_context_unavailable | role_unavailable)
```

All object key sets/enums are closed, data-only and deeply immutable after parsing. Safe integer
counts lie0..N with C<=P and P+Q<=N; chosen flags agree with source members; chosen centre implies
chosen pawn and chosen pawn/queen are exclusive. A chosen true count is at least1 while a chosen
false count is below N. SourcePly,
event/node/phase/owner/cut/ref ordering and complete cardinality join actual original scope values,
not just parser plausibility. N is legalUcis.length, not a second divergent stored number.
Retain all selected decisions, including N=1, unanimous, all-false and typed-unavailable entries.
At this version, the four source factories supply complete values or genuine available/empty
matches, not a dependency-unavailable arm. Only a directly absent optional worker context maps to
source_context_unavailable; known unsupported role maps to role_unavailable. A supplied but copied,
crossed, retired or failed context, illegal chosen identity, malformed source, failed consumer or
unknown execution error throws and rolls back. No speculative source_unavailable member is added,
and no arbitrary exception is caught as absence.

The whole family is one closed result; a missing, invalid or wrong-cut document is an unavailable
run outcome, not an empty decision list. Use the existing completed job source identity for
currentness and the existing short snapshot/complete-cut protocol; no new cache key authority.
Storage verifies original issuing scope/computed result before publishing, including unchanged
old completed rows on failure, zero/duplicate/out-of-scope family rejection and source changes
at rebuild's final check. Strict migration and account deletion/export/restore enumeration include
the family; portable import rederives it from verified sources rather than trusting uploaded facts.

The existing closed longitudinal query gains includeChoiceFacts?:true, constructed before query
branding, and a separate typed choiceFacts outcome lane. Only opt-in reads the family; omitted
opt-in leaves existing callers unchanged and does not touch the new table. The lane has exactly
one outcome for EACH requested complete owner/run/cut/revision, including typed ineligible,
missing and invalid outcomes; duplicates or crossed tuple/owner/current-source refs refuse.
Owner/run/session/pack selection chooses the same complete run population as the snapshot.
Decision phase/class/projection filters must not truncate this family document or its decision
metadata. The later metric applies rooted index<16 to the full stored decision list. A missing/
invalid lane blocks choice metrics only; it cannot erase existing observations or run history.

## 4. Profile adoption and missing data

All overview/card/detail/denominator/contributor/consented-share paths consume current parsed
choice documents. Cached raw helpers cannot override a replaced/missing/invalid result or an
owner/source change. Reuse existing actual owner and completed job source identity cache admission;
do not add another cache/source-hash protocol. Warm reads do not re-open V4 or invoke collectors.

For each retained decision, residual is chosen - count/N. Forced/unanimous zeros stay in the
decision count. Sum residuals over retained decisions and divide by their count, retaining the
existing by-game resampling and floors. Early-queen selects original BEFORE sourcePly<16.
Shares may be derived from counts, not stored as a second disagreeing denominator. Missing source
within the selected metric makes that whole metric incomplete before floor/bootstrap arithmetic;
it cannot silently drop a decision/game, lower a denominator or invent a zero. A missing field
outside a metric's actual selected scope cannot block that metric.

Retain original game/cohort and generic decision metadata independently of choice availability;
other cards must not disappear when choice sources are absent. Audit ALL GameFact.decisions
consumers, including skill decision construction, game refs and castling baseline/contributors.
They must not require guessed trait flags or an invented empty legal population to stay alive.
Where a consumer really needs legal identities, missing choice source is explicitly unavailable;
current unadmitted skill leaves do not acquire credit from this migration. Preserve D4147 GAME
first-owner/first-source/raw-first-retained decision distinctions and all existing rights joins.
Human-facing missing text names the chess data; never disclose primitive/schema/RFC names as help.
