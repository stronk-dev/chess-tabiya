# Shared candidate packet — repeat-return closure

**Date:** 2026-08-28
**Question:** Can the shared complete-candidate population be cached once and reused by semantic
selection, Review, Support and future bot policy without inventing consumer authority, a production
bot, an unmeasured engine topology or a false aggregate evidence identity?
**Verdict:** `[V]` Yes at the authoring tier, as one neutral process-sealed execution receipt over
individually declared evidence. It is not itself an F1 projection. Production remains absent and
the RFC remains pending repeat independent review.

## Evidence

The 2026-08-27 repeat review found four independent contradictions: the cache returned a
consumer-specific view while its key omitted the consumer; the static derivation graph carried no
value-level member witness; a test-created profile stood in for an empty production bot roster; and
N child Stockfish searches replaced the measured one-root legal-table operation. `[V]`
`planning/evidence-foundation-ux/shared-candidate-packet-repeat-review-2026-08-27.md`.

The cache repair is one process-sealed `CandidatePopulationReceipt` with no consumer field or view.
The real semantic-check operation consumes that receipt after lookup. Source tracing found no
semantic-selection caller or route in `createApplication`, so the executable—not a dormant
application dependency—is the first composition root ([[D1947]]). No opponent operation is injected
while `BOT_POLICY_PROFILES = compileBotPolicyCatalog([])`. The held bot handoff joins the exact
packet legal set to one `ProviderEvidenceDelivery<StockfishLegalRootTable>` in a literal
`root_side_to_move` score frame; it does not open a search per child. `[V]`
`rfc/shared-candidate-evidence-packet.md` §§3.1, 6.0, 7.1–8.3;
`tools/d1900-candidate-packet-amendment-harness/candidate-packet-contract.test.mts`.

Re-deriving the shipped F1 types found a fifth contract failure beyond the return. One
`EvidenceDerivation.inputs` member is a conjunction; `anyOf` is a closed set of alternative
conjunctions, and semantic-event runtime seals retain the complete member actually used. A packet
for one position contains only a position-specific subset of the possible 47 event and 22 reading
identities. The former scope-wide declaration could compile because the manifest validated ids,
cycles and inheritance, not because every listed value occurred. `[V]`
`packages/runtime/src/evidence-contract.ts:19-21,305-309,525-541,564-572`;
`docs/evidence-contract.md:71-75`.

The truthful repair removes `derived.candidate.event_population@1`, its adapter and its two
future-only bindings. Legal moves, retained semantic events and retained readings preserve their
existing exact F1 identities and original object references inside the private receipt. The
possible collector closure remains a code-derived migration/coverage registry, never a claim that
all members fired. Downstream Review, Support and bot operations must declare only the particular
derived conclusions they actually construct. `[V]` `rfc/shared-candidate-evidence-packet.md` §3.1,
§5.3, criteria 22–24.

## Falsifier

`make candidate-packet-contract` passes 8/8 through the repository-owned toolchain. Its negative
controls reject consumer authority in the cached receipt, forged/equal-rebuilt references, a
synthetic bot traversal, incomplete or wrong-root score tables, bare provider payloads, future-only
packet bindings, a complete possible-vocabulary list presented as one value's inputs, and a dormant
`createApplication` injection. `[V]`

## Limits

This closes an RFC authoring return, not production. It does not implement the compiler/cache,
select Support content, rank Review moments, define a bot personality, or clear the release memory
ceiling. The first implementation remains blocked on repeat independent review; the bot join also
depends on accepted provider execution and a concrete accepted bot profile/route. `[V]`

## Consequence

The packet can remain the shared denominator for evidence selection without becoming a second
evidence authority. This preserves the foundation split: collectors establish facts, the packet
shares complete alternatives, and each end feature owns its significance/disclosure derivation.
The RFC should now receive repeat independent buildability review against this exact boundary.
