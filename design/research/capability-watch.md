## 3. Coverage and honest omissions

The 17 covered map families include guidance, analysis/theory, review, drills, bots, profiles,
campaign, coach, streamer, human play, bot events, self-host/open posture, responsive workflow and
integrations. Four map families have no market representative in this seed:

- `Evidence foundation` and `Semantic move understanding` are enabling truth architecture, not
  competitor-facing features;
- `Capability watch` is this process itself;
- `Federation/discovery` is intentionally post-1.0 and waits on R17/O14.

That is not an automatic gap. The checker reports it so a later product can be attached only when
it contributes evidence. `[V]` `coveredMapFamilies`/`uncoveredMapFamilies`; `[M]` interpretation.

The targeted pass queried every formerly unchecked row. A `not_found` cell records that the exact
product/workflow search did not yield feature-specific independent user evidence; it is neither a
positive signal nor a claim of absence. D554's forum arm is therefore complete while its comparable
hands-on arm remains distributed across R3/R7/R8/R11/R15–R17. `[V]`
`design/research/competitor-love-hate-sweep.md`.

## 4. How to maintain it

1. Add or update the canonical product once.
2. Add a row only when the product supplies new evidence for a capability.
3. Record vendor capability, love signal and hate signal separately.
4. State the Tabiya transformation and the mechanism explicitly refused.
5. Bind producers, consumer, current status and research/decision/RFC route.
6. Run the checker; a clone does not create coverage and a novel capability appears unbound.

This closes D556's missing instrument and D554's targeted desk/forum arm. It does not claim hands-on
coverage, authorize any feature, or replace the consumer-specific studies R3/R7/R8/R11/R15–R17. `[M]`
