# O11 owner handoff — coach and streamer workflows

**Status:** ready for owner ruling on composition; Teacher mechanism already accepted  
**Inputs:** R3/R7, R15/R16 current conformance, O4, D636, accepted `teacher-surface`

## Recommended ruling

1. **No new evidence modes.** Coach and Streamer are workflow presets over the shared manifest,
   run disclosure and modules. No per-viewer evidence fork and no coach-only classifier/LLM truth.
2. **Add an explicit Academy assistance profile.** It must not read/write Just Play's `position`
   preferences. F5 owns common module composition; F11 binds the Academy views. This amends the
   accepted Teacher RFC's older refusal of a seventh profile.
3. **Teach Live composition:** learner board defaults to legal sight plus post-commit
   pattern/theory guidance; coach controls proposals, possession and shared reveal. Direct moves,
   PVs and proactive prevention require an explicit Support/Analyze selection and stay within the
   session ceiling.
4. **Review Submission composition:** retain the accepted Teacher RFC exactly—finished, disclosed,
   learner-submitted run; reviewing teacher reaches the learner/host rail; no ambient history,
   progress mining, grading or class weakness dashboard.
5. **Streamer composition:** ship the current board/objective/branches/marks/vote/withholding
   overlay and explicit Stream preferences as 1.0. Host assistance may exist on the host screen but
   is never added to the overlay automatically.
6. **Adapter boundary:** core accepts only the existing authenticated, bounded, attributed tally
   API. Provider-specific Twitch/YouTube bridges own credentials and moderation as optional
   integrations; raw chat is not a core data plane.
7. **No Tabiya editorial delay for 1.0 Stream.** The run disclosure barrier governs evidence;
   two-second polling is transport only. Competitive/public-event delay remains R17/O12 rather
   than being inferred from self-directed streaming.
8. **Proceed with accepted Teacher implementation.** R15's external participant arm is out of scope
   under D649. Resolve active RFC migration/deletion wording normally, but do not make O11 research
   retroactively revoke the existing owner ruling.

## What remains owner-use validation

Module names, exact default budgets, layout density and whether the two workflows feel legible.
Owner use may reject those compositions; it does not reopen separate truth paths, ambient learner
surveillance or unsupported coaching claims.

## Consequence of approval

O11 is answered. `teacher-surface` stays executable; F5/F11 may draft only the explicit Academy and
Streamer compositions, provider-adapter interface and view bindings above. R17/O12 keep match,
tournament, public-event moderation and competitive delay.
