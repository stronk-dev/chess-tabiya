# Integrated 1.0 capability map

**Status:** proposed scope map for research and owner ruling; not a promise or implementation spec

**Owner ambition:** D555

**Sequencing:** D563

**Current-state audit:** A1, `capability-reality-audit.md` (2026-08-20). The state token in each
reality cell is integration reality, not a 1.0 scope ruling or learning-efficacy claim.

“One FOSS platform” means the workflows share identity, positions, evidence, history and return
paths. It does not mean copying every competitor screen or shipping unrelated modes behind one
navigation bar. This map makes every requested capability visible and gives it a route; the owner
still rules the final 1.0 boundary after the named research.

## Release vocabulary

- **1.0 core candidate:** necessary to make the individual rehearsal promise coherent.
- **1.0 breadth decision:** plausibly part of the integrated release, but its value/cost/workflow
  has not been researched enough to include or defer honestly.
- **post-1.0 candidate:** explicitly has a route, but is not a prerequisite for the first coherent
  release unless later evidence and an owner ruling promote it.

“Shipped” below means code exists. It does not override evidence that the UX is noisy, the feature
has no consumer, or the relevant gate remains unmet.

## The integrated default journeys

These journeys, not individual routes, define coherence:

1. **Play with guidance:** choose `Just play`, `Rehearse a plan`, or `Practice an outcome`; accept
   the recommended preset; commit; receive only the bounded support selected for that moment;
   rewind and compare.
2. **Review and return:** finish/import a game; scan a short grounded Review Map; open one moment;
   retry it, branch it, or enter a related drill/theory source.
3. **Learn theory by consequence:** find an opening/structure/motif; read a cited breadcrumb; play
   the resulting position; return with the result attached.
4. **Play a person, not an Elo knob:** choose a clearly described bot behaviour; the board play—not
   only its avatar/chat—expresses it; review what happened afterward.
5. **See yourself honestly:** inspect measured habits, concepts and uncertainty; follow a grounded
   suggested rehearsal; never confuse style, rating and advice.
6. **Teach or show:** a coach/streamer selects a workflow preset and audience; the same evidence
   modules are composed with different permissions and delay, not reimplemented.

If a proposed capability cannot enter one of these journeys or establish a necessary platform
floor, it is a post-1.0 candidate until an owner ruling says otherwise.
