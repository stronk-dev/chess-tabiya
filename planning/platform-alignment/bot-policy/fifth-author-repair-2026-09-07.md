# Bot policy — fifth author repair

Date: 2026-09-07

This is a bounded RFC authoring repair, not production implementation or acceptance.

## Closed locally

- [[D3025]]: every profile-bearing boundary resolves and compares the complete immutable catalog
  member; a genuine id/digest cannot carry substituted family, sampler or layer semantics.
- [[D3026]]: durable decisions reconstruct from a sealed replay authority containing independently
  loaded root, legal, classifier, catalog-profile and provider inputs; coordinated re-hashing does
  not authorize another move.
- [[D3027]] and [[D3127]]: both pre-provider and concurrent-winner replay load unknown bytes by
  request id and cross the same durable parser. Caller envelope parameters are gone.
- [[D3028]]: the public request is an exact four-field object with bounded non-empty node/branch
  identities and a canonical lowercase SHA-256 event-head digest.
- [[D3029]]: population equality requires unique identities and duplicate Stockfish move rows fail
  before lookup.
- [[D3032]]: both retained author TypeScript programs inherit `tsconfig.base.json`; absent optional
  values are omitted under `exactOptionalPropertyTypes`.

## Intentionally not closed

- [[D3030]] requires the shared provider layer's durable operation-specific parser/receipt. A
  bot-local self-digest or another disposable provider authority would reproduce the defect.
- [[D3031]] is narrowed: profile substitution now fails, but roster availability still must import
  the current accepted provider-health checkpoint. The older author model is not promoted into that
  authority.

fourth-author groups, and both TypeScript programs under the repository compiler contract.
`make provider-health-cut-contract` separately proves that retained draft evidence lives in
opt-in `verify-rfc-evidence`, not stable release governance ([[D3126]]).
