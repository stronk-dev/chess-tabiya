## What research has settled

1. The six-arm R4 experiment refuses semantic/vector retrieval as 1.0 authority. Exact+FTS reached
   97.7% recall@5 versus semantic 94.7%, while the semantic safety, abstention and artifact controls
   failed.
2. The useful Skipper extraction is an offline provenance compiler/builder, not its chat agent or an
   always-on runtime service. A release needs an immutable local bundle and no hosted secret.
3. R8 proves the workflow requires a typed applicability **set**, not “related text”: exact shapes,
   transposition keys and anchored claims can map to versioned theory and pack targets with honest
   empty results.
4. Position identity is not unique opening identity: 52 candidate records yield 49 transposition
   keys and three keys carry both a parent and descendant opening name.
5. R6 proves schema validity is not capability compatibility. Packs need required semantic
   capability versions, runtimes need a supported set, and migrations need read-only plans.
6. “Exercise every enum” is the wrong pilot rule. Four declared families have zero documents. A
   primitive is required only because a ruled 1.0 workflow consumes it; experimental/retired
   vocabulary must not force content into existence.

## O5 recommended ruling — 1.0 theory and builder posture

Approve all of the following as one contract:

- **Source posture:** a versioned allow-list of redistribution-compatible sources plus registered
  Tabiya shapes, principles and authored claims. Each entry carries source/revision URLs, source and
  span digests, licence/attribution, language, applicability keys and invalidation state.
- **Build posture:** a separate offline provenance compiler derived from the useful Skipper
  crawler/invalidation patterns. It may be a CLI or optional Compose builder profile; it is not a
  runtime dependency and does not expose Skipper's general agent policy.
- **Runtime posture:** ship a digest-addressed immutable local bundle. Exact typed applicability is
  authoritative; FTS is discovery/ranking only inside the already-eligible set. Vector/semantic
  retrieval is refused for 1.0 and may return only as a separately gated experiment.
- **Identity posture:** applicability returns a set of versioned theory identities plus zero or more
  launch targets. Display may use a declared specificity/source order but provenance keeps the full
  set. No LLM resolves ambiguity.
- **Rendering posture:** deterministic cited text is normative. An optional conforming LLM may
  shorten/rephrase admitted spans; it cannot select the passage, theory identity or drill.
- **Empty posture:** theory-only, drill-only, both and neither are first-class outcomes. No result is
  replaced by generic coach prose or an engine line.

This opens F4's provenance compiler RFC. It does not yet open F7, which also needs F3/F5 and the O6
contract below.

## O6 recommended ruling — stable extension and re-authoring budget

### O6.1 Capability contract (ready now)

Approve R6's six-part model: immutable released artifacts; pack-required/runtime-supported semantic
capability versions; evaluator semantics versioned independently from JSON fields; one read-only
migration planner plus explicit applier; deprecation with successor/refusal; and a sacrificial pilot
covering every **required** 1.0 capability.

F3 may implement this framework before the final pilot list exists. It must not choose UX defaults,
add chess primitives, apply the corpus plan or lift Gate F.

### O6.2 Re-authoring budget (owner choice ready now)

**Recommend:** a graduated official pack has a **zero forced semantic-rewrite budget** within 1.x.
Changed meaning receives a new capability version; old meaning remains supported or the new runtime
refuses that pack explicitly. Mechanical migrations may touch any number of files only when the
read-only plan is complete, deterministic and has zero unresolved chess/provenance judgments.

Before graduation, a deliberately named sacrificial pilot may be rewritten as needed. Any migration
requiring human chess judgment outside that pilot stops and returns to the owner with the exact
population; it never becomes an automatic content wave.

Alternative if supporting old meanings is judged too expensive: set an explicit non-zero pack/hour
limit per breaking release. Research cannot choose that limit. The zero-rewrite recommendation best
matches the owner's “foundation rock solid before content” ruling.

### O6.3 Required pilot membership (not fully ready)

The rule can be settled now even though exact members remain downstream:

- derive requirements from compiled 1.0 workflow consumers, not schema vocabulary;
- cover opening, middlegame, endgame, cross-phase and pack-free/empty paths;
- exercise provider-off, no-theory, no-drill, accessibility/gesture and Review re-entry;
- mark zero-use `engine_condition`, per-leg shape/policy and prediction capabilities
  experimental/retired unless a ruled workflow actually adopts them;
- use the smallest existing draft set that reaches all required cells; author only a missing
  sacrificial witness, never a scale wave.

F5/F7 and owner use determine the final matrix. R10 may test learning claims on that pilot, but it
must not block F3's compatibility framework or force speculative primitives into it.
