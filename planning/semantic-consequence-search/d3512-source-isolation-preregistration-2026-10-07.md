# D3512 — separately identified case-isolation successor protocol

This is a preregistered disposable research protocol, not production recovery,
an accepted search profile, a completed measurement or a reason to overwrite the
original depth-twelve capture. D3512 already owns the missing independent source
attempts; D3262 still owns the full cost/profile question.

## Why a successor is necessary

The original batch shares one `CostStockfish` adapter. After its first fatal
deadline, later `send` calls fail before writing another UCI command. The
preserved archive contains one initial deadline and 699 inherited dependency
failures across 697 cold rows. Retained rows are not independent attempts. [V]
`d3262-source-lifecycle-2026-10-07.md` and the original eighteen source images in
`d3262-cost-live-recursive-depth12-2026-10-07.json.gz`;
`cost-source-lifecycle.test.mjs`.

## Population and custody

Before execution, derive and freeze an explicit ordered successor case list from
the original archive, its metadata and `d3262-cost-plan-v1.json`. Select the
**697 original cold rows carrying deadline failures**, retaining each whole
cold/warm/provider-offline triplet: **2,091 successor cases**. Selection includes
the first fatal row, not just later fast refusals. Do not repeat the already
successful cold rows, select by a target verdict, or replace the six separately
invalid-PV rows. The list must bind every original case identity and raw-capture
digest, plus original archive, plan, source and successor-instrument digests.
The count is a selection expectation to check, not authority to trim a mismatch.
[V] Original ordered audit/table in `d3262-source-lifecycle-2026-10-07.md`;
`cost-contract.mjs` `caseIdentity`/`costCases`.

Store this list, lifecycle receipts and captures under a new successor identity
with exclusive-create writes. Keep the original failed archive and all of its
clocks unchanged. Old and new rows with the same case identity must never enter
the existing single-attempt reader as if they were unique cases. A separately
tested qualification join must declare which original gaps each successor
attempt addresses, preserve both results and refuse missing, extra, duplicate,
crossed or success-selected substitutions. Do not publish a promoted setting
count before that join and independent replay pass.

## Isolation, not retries until success

Use concurrency one. Each successor cold case receives a **new, initialized UCI
process** with the original binary/configuration identity, Threads=1, Hash=16,
Chess960=false, clear hash per query, original depth-twelve budget, original
MultiPV/event widths and unchanged traversal/node/deadline limits. A different
binary/configuration must be reported as a different-source sensitivity, not
silently admitted as filling this original-source qualification.

Record process startup/readiness before the ordinary request-ready case clock,
matching the original preregistration's visible startup boundary. Separately
record startup, case execution, teardown and their enclosing interval. Do not
add startup to only one comparator, hide it, subtract it from an operation, or
call request-ready duration first-use/browser latency. Parent and child memory
remain separate observations. [V] `d3262-cost-preregistration-v1.md` §Actual
execution, caches and clocks; original `cost-stockfish.mjs` configuration.

Within a cold case, retain the original query and cache behavior. **No failed
query or case is retried.** A timeout/crash remains a typed partial result;
subsequent dependencies within that same failed case may still be inherited
refusals and must say so. A lifecycle receipt binds query-command emission,
process identity, first fatal boundary and inherited refusals. If readiness
itself fails, retain that startup failure explicitly; do not claim an emitted
search or a measured search timeout. A fresh process for the next cold case
prevents that failure from poisoning unrelated later cases.

Warm consumes only admitted receipts from its matching successor cold case,
never the original failed batch, an earlier candidate or a fresh search. Close
the cold process before warm execution and make any warm execution request fail
the instrument. Offline begins with no receipts and denies source execution;
it does not launch an engine to manufacture an outage. No-target cases do not
belong to this failure-selected successor list; the original no-target rows
remain in the whole-population qualification denominator.

## Required controls before native execution

Use real disposable subprocesses to establish all of these boundaries before
the successor's live capture:

- A first cold case writes a command, then dies or times out; the next cold case
  writes to a different, newly initialized process and can finish. Neither case
  is retried, and the first failure remains in the receipt.
- Multiple failures still retain one attempt per declared cold case; no
  success-only resampling or inherited suffix mislabeled as independent work.
- Nonfatal invalid-PV admission remains invalid, not a recovery trigger or a
  reason to weaken canonical parsing/depth completion.
- Matching warm receipts preserve compiled evidence; missing cold receipts stay
  unavailable, and any warm fresh-query attempt is refused.
- Offline execution/reuse, crossed process/source identity, omitted startup or
  teardown, false command-emission claims, overwritten output and altered
  original source/capture digests are rejected.
- The qualification join rejects changed selection lists, failed originals
  removed from reporting, arbitrary replacements and duplicate attempts counted
  as larger candidate populations.

Synthetic controls establish lifecycle/custody, not Stockfish/chess/timing
performance. Native successor results still require independent source/board/
observation/quantifier replay and explicit failure-aware stratification. Compare
source-isolated request-ready costs with the original shared-process boundary
only with that lifecycle difference stated; they are not interchangeable
machine-repeat trials or a naturally occurring outage distribution.
