## What was measured

[V] The retained `tools/r2-selection-harness/imported-sample.pgn` supplies the first
game with at least 80 plies, exactly the selection used by
`apps/server/src/longitudinal-worker-performance.test.ts`. Real imported runtime

the real legal-alternative enumerator, collectors, seals, registry or row algebra.
This isolates projection CPU cost; it does not measure import HTTP latency, queue
wait, SQLite publication or worker startup.

[V] Each side uses separate fresh Node 24 processes for unprofiled timing and CPU
sampling. The timing process first runs the ordinary production projector, then
its warm repeat, then an injected wrapper that recollects every edge through the
same production semantic closure without membership reuse. Full serialized output
is byte-identical across those three paths; all per-decision checkpoints remain.
The profile process separately samples its first complete collection and checks
the same output/control invariants. Node is v24.21.0, macOS arm64, 14 logical CPUs;
the development host is heavily loaded (one-minute load about 50). These are three
observations per cell, not a distribution or a cross-host latency guarantee.
