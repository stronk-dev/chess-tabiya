# Foundation source-repair authoring wave — 2026-08-26

**Purpose.** Convert the 2026-08-26 evidence audits into one buildable RFC/amendment sequence. This
is a routing document, not implementation authority and not a replacement for the semantic
handoffs. The rule is simple: source truth and identity land before selection or UX consumes them.

## Why one wave

Sixteen `*author-repair*` / `*author-handoff*` files now exist in the evidence-foundation program.
One bounded-policy repair lives in its own program and Review has a downstream compiler
checkpoint. Several touch the same compiled manifest, semantic-event registry, structure/pawn
readers and module accepts. A file-by-file queue would repeat the defect D1726 measured: coarse
legacy facts remain live while richer successors are “implemented” beside them. D1736 therefore
orders the shared seams once.

## RFC ownership decision for Claude

Prefer one **source-identity amendment RFC** covering the stage-1 version vocabulary and shared
runtime/catalogue files, then amend the active collector RFC discharge tables to point to it. Do
not independently amend seven RFCs that all claim the same manifest/semantic files. If the register
or lane claims force a split, split by shared-resource ownership—not by chess term—and record the
landing order here.

Likely parents/readers:

- `semantic-collectors.md`: shared semantic source/event operation and Wave-C additions;
- active `tactical-collectors.md` / `breadth-collectors.md`: keep implemented histories and amend
  discharge/consumer mappings rather than pretending v1 payloads never shipped;
- archived F1/F2 contracts: supersede through a living amendment, never edit archive;
- `module-registration.md`: stage 5 only, after exact ids and operations are compile-visible;
- bot-policy/candidate packet, Review and longitudinal RFCs: downstream consumers, not owners of
  chess source semantics.

## Buildability checks

1. Every changed projection id has exactly one versioned payload authority and one declared
   producer operation.
2. Current pack predicates and digests remain byte-stable unless the RFC lists a dry-run migration
   and human semantic review.
3. Every new event has independent able-to-fail fixtures before becoming eligible.
4. Provider latency/absence/confidence is inherited through every derivation path.
5. Ordinary module accepts contain no superseded legacy raw family.
6. Advanced can still inspect source inventory with provenance.
7. Review, bot, style and drill consumers point to the same projection ids, with their own
   eligibility/selection rules rather than duplicate detectors.
8. The compiled manifest, production operation census, semantic validation matrix and module
   registry are set-equal at wave close.

## Exit

order, and every source-program handoff in the literal inventory is claimed exactly once.
Implementation closes source rows and defects in its own commits; module/UX completion remains
