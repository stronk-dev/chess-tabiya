## Blocking findings

### D2530 — provider source factory is a type, not the injected value

The generated success pipeline calls
`ProviderSourceFactories[request.operation].make(result.delivery)`. The provider RFC declares
`ProviderSourceFactories` only as a mapped type. Its runtime value is
`ProviderTraversalApplication.sourceFactories`. The stated operation cannot execute and gives an
implementer an attractive reason to create a second registry. Bind the real injected application
value and keep its operation generic correlated through assertion and factory call.

### D2531 — catalogue gate inputs have no exact evidence identities

`CatalogueEvidencePoolRequest` accepts a sealed `DeclaredEvidence<CanonicalPositionIdentity>` and
`DeclaredEvidence<TheoryApplicabilityIdentity>`, but neither its ABI nor generated source row names
the exact producer/projection ids authorized for those roles. A generic F1 seal proves only that
some declared evidence constructed the value. It does not prove that the value is the canonical
position or applicability authority. Declare the two exact input identities and reject crossed,
otherwise-valid declarations.

### D2532 — eval delta's inner and outer subjects disagree

The occurrence contract correctly says `same_recorded_branch` and `consecutive_trail_order`, but
the enclosing row remains `subjectKind: branch_pair`, uses `recorded_branch_pair` and joins through
`declared_branch_pair`. The exact-operation compiler cannot implement both meanings. Route the
existing projection through its true same-branch transition/window authority; use a separately
named projection if a cross-branch comparison is wanted.

### D2533 — the check arm is outside deflection's dependency closure

The new check-induced occurrence alternative requires `rules.tactic.event.check` at edge 1, while
the row's `derivation.inputs` and `inputBindings` omit it. Adding it to the current `kind: all`
would make check mandatory for the bait-capture alternative. The derivation needs common inputs
plus literal per-alternative inputs/bindings, crossed against both authoritative detector arms.

### D2534 — every pair pointer misses the receipt key set

All 205 `timingRequirement.resolutionOwner.pair` values are
`<module>@1\0<projection>@1`. The top-level required set and presentation pair use
`module.<module>@1\0<projection>@1`. The author control compares the duplicated top-level sets and
never joins each row pointer to them. No row can be discharged by the receipt it names.

### D2535 — the sole final receipt is structurally forgeable

`ModuleExactOperationResolutionReceipt` is a plain interface returned by a declared function. No
constructor-owned seal, runtime assertion or brand exists, although final F1 emission accepts it as
the sole authority. A cast or spread can bypass source blockers, non-null operation resolution,
timing intersection and set equality. Seal the compiler result and require its assertion at the
emitter boundary.
