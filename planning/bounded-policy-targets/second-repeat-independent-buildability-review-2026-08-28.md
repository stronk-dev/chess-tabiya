## Blockers

### 1. The “registered” pass transform is a private duplicate ([[D1962]])

`threats()` implements the convention inline by flipping turn and clearing en-passant. It exports
the convention id, not the transform. The author harness defines a second `passFen()` and the RFC
implementation surface does not touch `tactics.ts`. A later change to `threat@1` can therefore
leave target admission applying different chronology while both inputs remain properly sealed.

Repair by exporting/versioning one pass-anchor operation used by both `threats()` and the target
join, or by amending threat evidence to retain the exact source/passed anchor pair. Do not copy the
three current mutation lines into a third file.

### 2. Initial promoted identity is unavailable ([[D1963]])

`LegalExchangeResult` carries only colour, role and square for capturer/captured. Threat target bytes
also omit promotion provenance. Standard FEN cannot distinguish an original queen from a promoted
queen already on the same square; chessops parses the board byte with `promoted:false`.

Repair by removing initial promoted provenance from `TrackedPieceIdentity`. Promotion observed
inside the bounded line remains exact and should update the tracked role/state from that edge. A
history authority would be a different, heavier contract and is not needed for this local fact.

### 3. `target_captured` is impossible ([[D1964]])

The threatened victim belongs to the original side to move. The candidate is a legal move by that
same side. It cannot capture its own victim. The D1023 algorithm omits this cause and records zero
identity losses; the author type added the branch without a legal fixture.

Remove the member. Keep `attacker_captured`, `target_moved`, `capture_illegal`,
`exchange_neutralized`, `preserved` and genuinely unexplained identity loss. “Every legal
combination” must mean reachable combinations, not a symmetric-looking enum.

### 4. Background/cancellation is metadata, not execution ([[D1965]])

The implementation surface contains only a runtime function returning a promise over synchronous
enumeration. It names no worker, queue, injected yield or cooperative chunk. An abort scheduled by
a disconnected request cannot run during that same event-loop turn. A consumer can import the
operation and block inline despite the declaration saying `background`.

Specify one bounded background job service. Because F1 seals/reference identity do not survive
structured cloning automatically, the lowest-risk repair is cooperative main-process enumeration
with a bounded queue, injected portable macrotask yield, cancellation checks at a stated node
interval and measured maximum cancellation latency. A worker design needs an explicit
serialize/revalidate/reseal receipt first.

### 5. The 512-pair ceiling has no set-owning request ([[D1966]])

The public operation derives one named target, one immediate candidate or one bounded return. No
call owns the complete target and legal-candidate populations. Unlimited individually valid calls
therefore evade `multiplication_limit` by construction.

Make the background job admission own the complete source threat/exchange/legal-move authorities,
derive the target set, calculate exact `targets × candidates`, refuse above 512, and only then run
the per-item helpers. Alternatively move this ceiling to the later composition layer if that is the
first operation that genuinely owns both sets; do not claim enforcement here without an owner.

### 6. Request kind does not determine result kind ([[D1967]])

`derive(BoundedTargetDerivationRequest): Promise<BoundedTargetDerivationResult>` accepts every
cross-pair. A named-target request can return bounded-return evidence; an immediate request can
return `exchange_mismatch`; cancellation/multiplication reasons can claim any projection. The
crossed type witness compiles cleanly.

Publish a distributive request→evidence/abstention map or three exact descriptors. Each request kind
must determine its sole success projection, legal reason set and legal optional fields. Cross every
wrong pair at compile time and runtime.

### 7. The bounded result can seal contradictions ([[D1968]])

Independent booleans plus nullable `string[]` witnesses admit universal survival with existential
false, false-with-witness, true-without-witness and arbitrary line lengths/dialects. The public
adapter boundary therefore needs more than required-key checking.

Prefer a discriminated algebra: `not_reintroduced`, `reintroduced` with a canonical four-move
witness, or `survives_every_defence` with its witness; derive compatibility booleans rather than
store duplicate truth. Otherwise specify one mandatory validating constructor and make every
adapter call it. Universal survival implies existential return and cannot carry a refutation.

## Amendment order

1. Repair the one threat-pass authority and remove unavailable promotion provenance.
2. Remove the unreachable immediate outcome and cross all reachable causes on real positions.
3. Replace the payload with a discriminated witness/refutation algebra.
4. Correlate each request kind with one exact success/abstention result.
5. Add the set-owning batch admission that can enforce 512 pairs.
6. Define the bounded background queue/yield/cancellation topology and measure cancellation after
   work begins.
7. Re-run the author, repeat-review and exhaustive census targets against the amended contract,
   then repeat independent review.

No owner chess judgement is required. These are source authority, reachability, type and execution
contradictions. Provider/policy work remains correctly separate.
