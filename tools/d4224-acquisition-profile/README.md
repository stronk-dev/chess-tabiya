# D4224 — current source acquisition profile

Disposable evidence instrument. No production source, source issuer, learner policy or budget
changes. Run normal commands from the repository root:

```sh
make acquisition-profile-smoke
make acquisition-profile-measure
```

The builder produces ordinary and instrumented copies of current source in `.cache/`. Exact
named synchronous bodies receive span entry/finalizers. Reading counters wrap only actual
cache-miss computation; a digest counter observes the existing fallback without changing it.
Guards refuse missing, duplicate, repeated or unexpected sites. Erasing only the observer
syntax must recover the exact original source. Production files stay untouched.

Before timing, fresh ordinary and active-counter workers compare the complete32-decision
packet/foundation/outcome/availability graphs and all traversed value receipts. Repeated
calls within each side must retain original prerequisite identities. The normal64-entry
application service and every one of the thirteen families are used. PGN setup precedes
the clocks. Actual compiler/row/family counts, nonzero reading misses and physical mapping
are checked after the run, rather than accepting an empty observation.

Three separate fresh workers measure the ordinary source interval, a CPU sample on ordinary
source bodies and the instrumented interval/sample. This is one ordered diagnostic, not a
counterbalanced performance comparison. A real failure control proves profiler disconnection
and trace-owner removal after an exception.

Inclusive spans overlap and cannot be added. Self spans subtract nested observed boundaries,
but include uninstrumented work and observer overhead. CPU leaf samples aggregate by function
location across recursive contexts; they are approximate attribution, not exact elapsed time.
The separate ordinary-source sample avoids treating millions of span-wrapper calls as the
source's real distribution. Module comments and nearest callers are hints.

The report contains one compact numeric decision table, equality digests, span/call counters
and top CPU aggregates under64KiB. Raw profiles, full payloads and recordings are never saved.
Results identify follow-up experiments; they do not prove an optimizer, ordinary consumer,
production latency, appliance memory limit or complete D4224/D4225 resolution.
